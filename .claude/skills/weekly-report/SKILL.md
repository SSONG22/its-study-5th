# 주차 보고서 작성

`docs/weekly/wNN.md` 를 쓴다. 매주 같은 형식으로 쌓여야 8주차에 비교가 된다.

## 원칙

**숫자는 반드시 측정 파일에서 읽는다.** 대화 기억이나 이전 보고서에서 가져오지 않는다.
3주차에 표본 6건만 보고 "무료 서비스는 캐시 지표를 안 준다"고 썼다가 90건을 돌린 뒤
정정한 적이 있다. 근거 파일을 먼저 열고 거기 있는 값만 쓴다.

**측정하지 않은 것은 쓰지 않는다.** 추정값을 쓸 때는 추정이라고 밝힌다.

**예상은 측정 전에 쓴다.** 결과를 보고 예상을 맞춰 쓰면 기록이 쓸모없어진다.
지난주에 적은 예상은 틀렸더라도 그대로 옮긴다.

**수식어를 쓰지 않는다.** 금지 표현:

- 극적 표현 — "치명적", "최악", "~할 뻔했다", "죽어 있던", "놀랍게도"
- 평가 부사 — "매우", "훨씬", "압도적으로", "제일", "확실히"
- 뜸 들이기 — "그런데 더 큰 게 있었다", "여기서 반전은"
- 구어체 어미 — "~더라고요", "~거든요", "~잖아요", "~했어요"

사실과 숫자로만 쓴다. "window 가 최악이었다" 대신 "window 는 입력 토큰 9% 절감,
기억률 97% → 10%".

**기록식으로 쓴다.** `~했다` 보다 명사형·개조식을 쓴다. 문장보다 항목.

**어려운 용어는 풀어 쓴다.** 처음 나오는 용어는 괄호로 원어를 병기한다.
예: 재사용(프롬프트 캐싱), 안내문(시스템 프롬프트), 첫 글자까지 걸린 시간(TTFT).

## 읽을 파일

보고서를 쓰기 전에 아래를 모두 확인한다. 없으면 없다고 쓴다.

| 파일 | 쓰임 |
|---|---|
| `bench/results/*-summary.csv` | 전략별 집계값 |
| `bench/results/*.json` | 개별 측정 결과. 실패 사례와 실제 응답 확인 |
| `runs/*.jsonl` | 서버가 남긴 요청별 기록 |
| `git log --oneline` | 이번 주 커밋 |
| `git status --short` | 미커밋 변경 |
| `docs/weekly/w{NN-1}.md` | 지난주에 적은 "다음 주 할 일"과 "예상" |

집계가 필요하면 재계산하지 말고 `node bench/analyze.mjs --label {LABEL}` 를 실행해 출력을 쓴다.

## 형식

```markdown
# N주차

YYYY-MM-DD

## 1. 이번 주에 한 일

### 제목
- 항목
- 항목

## 2. 결과

(측정값 표. 숫자 근거 파일 경로를 함께 적는다)

### 확인된 것
- 사실 + 숫자

### 틀렸던 것
(이전 주차에 잘못 적은 내용이 있으면 여기에. 없으면 절 생략)

## 3. 예상과 결과

지난주 보고서에 적은 예상을 그대로 옮겨 적고 실제와 대조한다.

| 예상 | 실제 | 맞음 |
|---|---|---|
| (지난주에 적은 문장 그대로) | (측정값) | O / X |

틀린 예상은 왜 틀렸는지 한 줄 덧붙인다. 맞은 것보다 틀린 것이 기록할 가치가 크다.

## 4. 공부한 것

이번 주에 새로 알게 된 개념·사실. 출처를 함께 적는다.

- 사실 — 출처(문서명, URL, 측정)

## 5. 다음 주 할 일

### 작업
1. 항목

### 공부할 것
- 항목

### 예상
다음 주 측정 전에 미리 적는다. 측정 후에 쓰면 의미가 없다.

- 예상 문장 (근거 한 줄)

## 구현
- 파일 경로 — 한 줄 설명
- 커밋 / PR 링크

## 남은 문제
- 항목
```


## 절차

1. 주차 번호와 날짜 확인. 모임은 월요일 22:00, 활동 기간 10/3 ~ 11/30
2. 지난주 보고서의 "다음 주 할 일"을 읽고 달성 여부를 1절에 반영
   지난주 "예상" 절을 그대로 옮겨 3절에 대조표를 만든다. 예상을 고쳐 쓰지 않는다
3. 위 표의 파일을 읽어 숫자를 수집
4. 측정 결과가 지난 보고서와 어긋나면 "틀렸던 것" 절에 정정을 쓰고,
   해당 주차 문서도 같이 고친다
5. `docs/weekly/wNN.md` 에 저장
6. 5절 "예상" 을 반드시 채운다. 다음 주 보고서가 이걸 대조한다
7. 커밋하지 않는다. 사용자가 확인한 뒤 요청하면 커밋한다

## 분량

100~160줄. 넘으면 서술을 줄이고 표로 바꾼다.
보고서에 발표 시간 배분이나 화면 조작 지시를 넣지 않는다. 보고서는 기록이지 대본이 아니다.
