# 3주차 — AWS를 걷어내고, 캐싱이 안 걸리고 있었다는 걸 발견하다

2026-10-19 (월) 22:00 · 발표 15분

---

## 한 줄 요약

인프라를 버리고 측정에 집중하기로 했고, 그 과정에서 **핵심 지표가 처음부터 죽어 있었다**는 걸 발견했습니다.

---

## 1. 결정 — AWS Lambda를 버렸습니다 (3분)

지난주에 AWS Lambda + API Gateway로 설계를 다 짜뒀는데, 이번 주에 걷어냈습니다.

### 판단한 방법

하고 싶은 실험을 전부 나열하고 **인프라 의존도로 나눠봤습니다.**

| 실험 | 로컬 가능 |
|---|---|
| 턴 수 ↔ 입력 토큰 선형 증가 | ✅ |
| 히스토리 전략 3종 비교 | ✅ |
| 프롬프트 캐싱 효과 | ✅ |
| 모델 라우팅 (비용·지연·품질) | ✅ |
| 동시 요청 한계 — OpenAI 429 | ✅ |
| 스트리밍 TTFT vs 전체 지연 | ✅ |
| 재시도·백오프 전략 | ✅ |
| max_tokens 조절 효과 | ✅ |
| 콜드 스타트 | ❌ |
| Lambda 메모리 ↔ CPU ↔ 지연 | ❌ |
| GB-초 비용 | ❌ |
| API Gateway 29초 벽 | ❌ |

**8개 중 8개가 로컬에서 됩니다.** 잃는 건 인프라 축 4개고요.

### 결정적이었던 것

**실험 반복 속도**입니다.

4~7주차가 전부 "손잡이 하나 바꾸고 전후 비교"인데, Lambda면 바꿀 때마다 빌드하고 배포해야 합니다.
8주 동안 실험을 몇 번 돌리느냐가 결과물의 질을 좌우하는데, 배포 사이클이 그걸 깎아먹습니다.

그리고 6주차 동시성은 **어차피 병목이 OpenAI rate limit**일 가능성이 높습니다.
그렇다면 서버가 Lambda든 제 노트북이든 결과가 같습니다.

> 리더님께 여쭤본 결과 AWS 사용이 필수는 아니라고 하셔서 결정했습니다.

### 포기한 것은 포기했다고 적었습니다

콜드 스타트, 메모리↔CPU 트레이드오프, GB-초 비용, 29초 벽.
아키텍처 문서에 "포기한 측정축"으로 명시해뒀습니다. 나중에 "왜 안 했지"가 되지 않게요.

## 2. 발견 — 캐싱이 처음부터 안 걸리고 있었습니다 (3분)

이게 이번 주의 진짜 수확입니다.

### 무슨 일이 있었나

프롬프트 캐싱 효과 측정이 이 프로젝트의 핵심 지표입니다. `cachedTokens`를 레코드 스키마 맨 앞에 뒀고요.

그런데 OpenAI 문서를 읽어보니 **프리픽스가 최소 1,024 토큰이어야 캐시가 걸립니다.**

제 입력 세트를 재보니 이랬습니다.

| 턴깊이 | 추정 토큰 | 캐싱 |
|---|---|---|
| 1 | 82 | ❌ |
| 3 | 124 | ❌ |
| 5 | 162 | ❌ |
| **10** | **265** | ❌ (759 부족) |

**턴10조차 기준의 4분의 1입니다.** 그대로 8주를 갔으면 마지막에 "캐싱 효과가 0이었습니다"라고 발표할 뻔했습니다.

계획은 세웠는데 **그 계획이 성립하는 조건을 확인 안 한 것**이 원인이었습니다.

### 어떻게 고쳤나

시스템 프롬프트를 **실제 서비스 수준으로 다시 썼습니다.**

기존엔 4줄이었는데, 실제 영어 회화 서비스라면 들어갈 것들을 넣었습니다 — 역할 정의, 학습자 프로필, 대화 규칙, 교정 정책, 난이도 조정, good/bad 예시 3쌍.

| 턴깊이 | 이전 | 현재 |
|---|---|---|
| 1 | 82 | **1,373** ✅ |
| 3 | 124 | 1,415 ✅ |
| 5 | 162 | 1,453 ✅ |
| 10 | 265 | 1,557 ✅ |

억지로 늘린 게 아니라 **원래 이 정도가 맞았던 겁니다.** 처음에 제가 너무 대충 썼던 거고요.

### 덤으로 알게 된 것

캐시는 **프리픽스가 바이트 단위로 동일해야** 적중합니다. 앞쪽이 한 글자라도 바뀌면 전부 미스입니다.

그래서 시나리오를 시스템 프롬프트 블록 **안이 아니라 뒤에 별도 메시지로** 뺐습니다.
블록 안에 끼우면 시나리오 20개마다 프리픽스가 달라져서 캐시가 하나도 안 걸립니다.

```
[시스템 프롬프트 ~1,340 토큰]  ← 모든 요청 동일. 캐시 프리픽스
[시나리오]                      ← 여기부터 가변
[history]
[현재 메시지]
```

## 3. 모델 — 캐시 할인율이 모델마다 다릅니다 (2분)

지난주엔 `gpt-4.1-mini`를 기본값으로 뒀었는데 바꿨습니다.

| 모델 | 입력 | 캐시 입력 | 출력 | **캐시 할인** |
|---|---|---|---|---|
| **gpt-6-luna** | **$0.10** | **$0.01** | **$0.50** | **90%** |
| gpt-5.6-luna | $0.20 | $0.02 | $1.20 | 90% |
| gpt-4.1-mini (기존) | $0.40 | $0.10 | $1.60 | **75%** |

기존 선택이 **가격은 4배 비싸고 캐시 할인은 가장 나빴습니다.**
캐싱 효과 측정이 주제인데 측정 대상을 깎고 들어가는 셈이었습니다.

그리고 **GPT-5.6 이상만** explicit 캐시 breakpoint를 지원하고 캐시 수명이 30분 이상 보장됩니다.
이전 모델은 implicit만 되고 5~10분이라 멀티턴 중간에 캐시가 날아갑니다.

`gpt-4.1-mini`는 지우지 않고 **할인율 비교축**으로 남겼습니다.
"같은 캐싱이라도 모델에 따라 절감폭이 다르다"를 5주차에 숫자로 보여주려고요.

## 3-2. 무료 공급자로 돌리기로 했습니다 (2분)

유료 API 결제를 아직 안 해서, 우선 **Groq 무료 티어**로 돌렸습니다.
OpenAI SDK 의 `baseURL` 만 바꾸면 되기 때문에 코드 변경은 거의 없었습니다.

```
OPENAI_BASE_URL=https://api.groq.com/openai/v1
OPENAI_MODEL=openai/gpt-oss-20b
```

Groq, Gemini, Ollama, OpenRouter 가 전부 OpenAI 스펙을 따라서 프리셋만 갈아끼우면 됩니다.

### 여기서 걸린 것 — 문서와 계정이 다릅니다

Groq 문서에 production 모델로 적혀 있던 `llama-3.1-8b-instant` 를 넣었더니 **404** 가 났습니다.
키 문제인 줄 알았는데 401 이 아니라 `model_not_found` 였습니다.

`GET /openai/v1/models` 로 계정에 직접 물어보니 Llama 계열이 아예 없었습니다.
가용 목록은 `openai/gpt-oss-20b`, `openai/gpt-oss-120b`, `qwen/qwen3.8-27b` 였고요.
**문서 말고 계정에 물어봐야 한다**는 걸 배웠습니다.

### 그리고 캐시 지표를 잃었습니다

무료 공급자는 `prompt_tokens_details` 를 반환하지 않습니다. 그래서 `cachedTokens` 가 안 잡힙니다.

처음엔 이걸 0 으로 떨어뜨리고 있었는데, 그러면 **"캐시가 안 걸렸다" 와 "잴 수 없다" 를 구분 못 합니다.**
두 결론이 완전히 다른데 말이죠. 그래서 레코드를 이렇게 고쳤습니다.

| 값 | 의미 |
|---|---|
| 숫자 > 0 | 캐시 적중 |
| `0` | 공급자가 보고했는데 미적중 |
| `null` | **공급자가 아예 안 줌 = 측정 불가** |

### 그래서 계획을 이원화했습니다

| 주차 | 실험 | 공급자 | 이유 |
|---|---|---|---|
| 3~4 | 기준선 · 히스토리 전략 | **무료** | 토큰 수는 보고되므로 충분 |
| 5 | **프롬프트 캐싱** | **유료** | 캐시 지표가 필요 |
| 6 | 동시성 한계 | **무료** | 무료 티어가 rate limit 이 빡빡해 429 를 쉽게 본다 |
| 7 | 스트리밍 TTFT | 무료 | |
| 8 | 최종 비교 | 둘 다 | **공급자 간 비교 자체가 결과물** |

### 유료 구간 비용을 미리 계산했습니다

실측 토큰으로 `gpt-6-luna` 단가를 적용했습니다.

| 구간 | 건수 | 비용 |
|---|---|---|
| 5주차 캐싱 (80건×3회) | 240 | $0.018 |
| 모델 비교 | 160 | $0.012 |
| 6주차 부하 | 160 | $0.012 |
| 8주차 최종 (80건×5회) | 400 | $0.031 |
| **합계** | **960건** | **$0.10 (약 139원)** |

1만 건을 돌려도 $1.11 입니다. **실제 제약은 사용량이 아니라 최소 충전 단위**였습니다.
대시보드에 월 한도를 걸어두고 5주차에 한 번만 충전하면 8주가 끝납니다.

## 4. 데모 (3분)

> 화면 공유 — 브라우저에서 실제 대화

- 시나리오 20개 중 선택 (카페, 공항, 면접, 컴플레인 대응 등)
- 스트리밍 on/off 토글
- 히스토리 전략 full / window / summary 전환
- **메시지마다 측정값이 바로 표시됩니다**

실제 화면에 찍힌 값:

```
TTFT 682ms · 719ms · in 1235 · cached 미지원 · out 74
groq/openai/gpt-oss-20b · 누적 1턴 · 입력 1235 토큰 · 출력 74
```

### 첫 측정에서 가설 하나가 확인됐습니다

같은 시나리오로 3턴을 이어가며 입력 토큰을 봤습니다.

| 턴 | 입력 토큰 | 출력 | 지연 |
|---|---|---|---|
| 1 | **1,225** | 41 | 885ms |
| 2 | **1,262** | 91 | 702ms |
| 3 | **1,312** | 79 | 699ms |

**턴당 40~50 토큰씩 선형으로 증가합니다.** 2주차에 세운 가설이 첫 측정에서 그대로 나왔습니다.
4주차 히스토리 전략 비교가 이 증가를 얼마나 누르는지를 보는 실험입니다.

TTFT 682ms 와 전체 719ms 의 차이도 잡힙니다. 지금은 응답이 짧아 간격이 작지만,
출력이 길어질수록 벌어질 것이고 그게 7주차 스트리밍 실험의 재료입니다.

영어 공부하면서 **캐시가 언제 걸리고 언제 깨지는지 눈으로 보게** 만들었습니다.
전략을 바꾸면 토큰이 어떻게 변하는지도 바로 보이고요.

### 구조

```
브라우저 → 로컬 HTTP 서버 (Node 22, 내장 모듈만) → OpenAI
                    ↓
            runs/{label}.jsonl  (요청당 한 줄)
```

외부 의존은 `openai` 패키지 하나입니다. HTTP 서버와 SSE는 Node 내장으로 구현했습니다.
CloudWatch가 없어지니 레코드를 파일로 직접 떨구면 돼서 **수집이 오히려 간단해졌습니다.**

## 5. 설계 판단 두 가지 (2분)

### 세션 상태를 서버에 두지 않았습니다

클라이언트가 history를 매번 통째로 보냅니다. 비효율적으로 보이지만 일부러입니다.

하나는 **이 구조 자체가 측정 대상**이라서고요.
다른 하나는 **부하 테스트 때문**입니다. 대화는 원래 순차적이라 병렬로 못 때리는데,
history를 미리 채운 독립 요청으로 만들어두면 아무 순서로나 동시에 쏠 수 있습니다.

턴10짜리 대화를 "10번의 순차 호출"이 아니라 **"턴10 상태의 요청 1건"**으로 압축한 겁니다.

### 버그 하나

OpenAI 클라이언트를 모듈 로드 시점에 만들어서, **API 키가 없으면 서버가 기동조차 못 했습니다.**
지연 생성으로 바꿔서 키 없이도 UI와 시나리오 API는 뜨게 했습니다.
